# VS Code Agent 扩展原型 V4

用浏览器打开 `agent-workbench.html` 查看 VS Code 内的扩展面板设计。HTML 是原型展示载体，正式产品仍是当前 VS Code 扩展。

## 布局与交互

- 以 VS Code 编辑区旁约 400px 宽的 Agent 面板展示，代码编辑区仅为环境示意。
- 参考 Codex 在 VS Code 中的面板布局：顶部为新建会话、历史记录和唯一的设置入口，中间为消息，底部固定任务输入框。
- 移除连接摘要旁重复的设置按钮，连接状态与模型合并显示在输入框底部。
- 新建会话保留已有记录；首次发送的内容作为会话标题。历史记录在同一个 Agent 面板内展开，点击后恢复消息和草稿。
- 对话页移除最近会话列表，历史记录只通过顶部历史按钮查看。预置记录标记为“演示”；可以新建会话后发送消息，再通过历史记录切回。
- 生成中切换会话时，演示回复仍写入原会话；每个会话的输入草稿与停止状态互相独立。
- 设置在同一个 Agent 面板内以淡入和轻微位移切换，独立占用面板内容区，不再插入消息流、挤压对话；未激活的界面不可获得键盘焦点。系统选择减少动画时直接切换。
- 设置内容独立滚动，底部固定“测试连接 / 保存设置”。返回或按 Escape 保留未保存的表单草稿、对话内容和输入草稿，再次打开继续编辑；保存后返回对话并短暂提示。
- 调整为统一的中性色、细边框、圆角输入框和线性工具图标；欢迎内容居中留白，仅保留两个轻量的示例入口。
- API 表单参考 Git 提交 `3a9023d` 中 `src/webviewHtml.ts` 的历史布局：API 地址、密码框 Key、可输入模型及“获取模型”、测试连接、保存。高级设置默认收起。
- 页面顶端的“预览场景”是原型工具，可切换日常对话、首次配置和修改确认，不属于扩展产品。
- 首次配置场景中保存后在原面板继续对话；修改确认场景中可以查看差异、允许或暂缓修改。
- 快捷任务填入输入框，发送、停止生成、新建会话均为演示。未接 API、未读取项目、未修改代码；配置和会话仅保留于页面内存，刷新后重置。

## 正式实现边界

`prototype/` 是用于确认布局与交互的独立演示，不连接真实服务。正式实现位于 `src/ui/chatWebview.ts` 和 `media/chat.html`、`media/chat.css`、`media/chat.js`，由 VS Code 扩展宿主处理会话、设置与 Agent 操作。

正式界面切换会话时会先停止并收尾旧任务，再恢复目标会话，不使用原型的并行演示回复逻辑。局域网 HTTP code-server 的 Webview Service Worker 限制仍需在目标环境验证；扩展保留原生终端和 QuickPick 作为备用入口。具体使用方式见仓库根目录 README。
